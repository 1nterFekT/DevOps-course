# Работа К3-01

## Последовательность событий:

1. Разработчик делает *push* или *pull request* в свою ветку
2. Как только разработчик совершает *pull request* в `main`, происходит старт тестов
3. Если тесты прошли успешно, то запускается сборка
4. Приложение готово к выпуску

## Схема

Изменение в рабочей ветке -> Pull request в main -> Тестирование (успешны - merge, неуспешны - ошибка)

## Сравнение с git-flow

У git-flow структура сложнее. Там и `develop`/`release`/`hotfix` и прочие ветки есть. Нам в такой избыточности необходимости нет, поэтому мы обойдемся довольно примитивной структурой

## Обратная связь об ошибках

Во время тестов, если появляется проблема, запуск отмечается провальным. В GitHub Actions это крестик возле коммита. Там есть логи, чтобы разработчик мог с ними ознакомиться и исправить.

## Является ли сборка образа автоматически deployment?

Нет, не является. Сборка - отдельный этап, там готовится сам артефакт. А вот уже на этапе deployment он может быть развернут где-либо
